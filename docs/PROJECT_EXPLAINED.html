OneClick ERP: DevOps ka poora safar

Is page mein ek hi jagah sab kuch hai: DevOps ke basic concepts, is project ka architecture, pipeline kaise chalti hai, humne step by step kya kiya, kahan atke aur kaise nikle. Sab simple Hinglish mein.

Jenkins apne aap code check karta hai, Docker image banata hai, AWS par store karta hai, aapko email karta hai, aapke "Approve" ke baad EC2 server par deploy karta hai, aur check karta hai ki naya version sahi chal raha hai. 1. DevOps basics (pehle concept clear karo)

Ye wo shabd hain jo is project mein baar baar aayenge. Har ek ka simple matlab aur ek desi example.

🔁 DevOps

Development (code likhna) aur Operations (server par chalana) ko jodne ka tareeka. Goal: code jaldi, safely aur baar baar production tak pahunche.

Jaise restaurant mein chef (dev) aur waiter (ops) ek system se kaam karein, taaki khana garam aur sahi table par pahunche.

🧪 CI (Continuous Integration)

Har code change par automatic checks chalna: lint, tests, security scan. Galti jaldi pakdi jaati hai.

Exam se pehle har chapter ka chhota test. Galti wahin pakdi gayi.

🚚 CD (Continuous Delivery/Deployment)

Checks pass hone ke baad code ko automatic server tak le jana. Delivery = deploy ke liye ready, insaan approve karta hai. Deployment = bina insaan ke deploy. Is project mein Delivery hai (approval gate hai).

Courier ready hai, bas aapke "haan" ka wait.

🛤️ Pipeline

Steps ki line jo har release se guzarti hai. Is project mein Jenkinsfile mein likhi hai.

Factory ki assembly line: har station par ek kaam.

🚧 Gate (Quality Gate)

Pipeline ka checkpoint. Fail hua to aage nahi badhega.

Airport security: bag mein gadbad, to flight nahi.

🐳 Container aur Docker

App + uski saari zaroorat (Node, libraries) ek dabbe mein pack. Har jagah same chalta hai. Docker ye dabba banata aur chalata hai.

Tiffin box: ghar ho ya office, khana wahi.

📦 Image vs Container

Image = recipe/blueprint (static file). Container = us image se chalta hua program.

Image = cake ki recipe. Container = bana hua cake.

🏪 Registry (ECR)

Docker images ka godown. Hum ECR (AWS ka registry) use karte hain.

Jaise GitHub code ke liye hai, waise ECR images ke liye.

🏗️ IaC (Infrastructure as Code)

Server, network, permissions ko code mein likhna (Terraform). Ek command se poora setup ban jata hai, aur dobara bhi same banega.

Ghar ka naksha. Naksha hai to same ghar dobara ban sakta hai.

🏷️ Immutable tag

Har image ka unique naam, jaise 8-a86f45df (build number + commit). Ek baar bana to badal nahi sakta.

Aadhaar number: ek insaan, ek number, kabhi duplicate nahi.

⏪ Rollback

Naya version kharab nikla to purane chalte hue version par wapas jana.

Phone update ke baad bug aaya, to purana version wapas.

🪝 Webhook

Ek system doosre ko event par khud call karta hai. GitHub push hote hi Jenkins ko batata hai "naya code aaya".

Doorbell: aapko baar baar darwaza check nahi karna padta.

2. App kya hai (OneClick ERP)

ERP = Enterprise Resource Planning. Business ke products, customers, orders, stock ek jagah manage karna. Ye app jaan-boojh kar chhoti rakhi hai, kyunki asli focus pipeline hai.

📊 Dashboard

Products, customers, open orders, revenue, low-stock alert.

📦 Products & Stock

Product banana, edit, delete, stock receive karna, reorder level.

👥 Customers

Customer add/delete.

🧾 Sales Orders

Order banate waqt ek hi transaction mein stock check, lock, minus. NEW → CONFIRMED → SHIPPED. Cancel par stock wapas.

🖥️ Server 2: App EC2

5. Pipeline ke 6 phases

Ek "Build Now" (ya ek git push) par ye sab hota hai. Code Jenkinsfile mein hai.

PhaseKya hota haiRelease rokta hai?
1. SourceGitHub se checkout. Image tag banta hai: <build>-<commit>-
2. Code Quality GateInstall → Lint → Type check → Unit tests → Migration safety → SAST → SCA → (SonarQube optional)Haan
3. Build & PushMulti-stage Docker build (non-root user, npm hataya), ECR par pushHaan
4. Container Security GateECR scan ka result padhna; CRITICAL/HIGH mila to failAbhi BAND hai (section 7 dekho)
5a. AI ReportClaude summary likhta hai, SNS email bhejta hai. Fail hua to rule-based reportNahi
5b. Manual ApprovalPipeline rukti hai (24 ghante tak). Sirf approver user "Approve & Deploy" daba sakta haiHaan (insaan)
6. Deploy to EC2SSM se /opt/erp/deploy.sh <image>. Health check fail = auto rollbackHaan
6b. Smoke TestJenkins bahar se /health call karta hai: status: ok aur naya version hona chahiyeHaan
🔍 Deploy ke andar exactly kya hota hai? (deploy.sh)
  • App server ECR mein login karta hai aur nayi image pull karta hai.
  • Sirf app container restart hota hai. Postgres chalta rehta hai, data safe.
  • App start par naye SQL migrations apply karti hai (har ek apne transaction mein).
  • /health ko 2.5 minute tak check karta hai.
  • Healthy nahi hua to purani image wapas chala deta hai aur build fail.
🔍 Approval gate kyun zaroori hai?

Saare automatic checks pass hone ke baad bhi ek insaan (team lead) release dekh kar haan bolta hai. Jenkins record karta hai kisne approve kiya. Ye audit ke liye important hai. Webhook se automatic build hone par bhi production tak bina approval kuch nahi jata.

6. Humne kya kiya (step by step timeline)

Is session mein jo hua, usi order mein. Har step ke saath "kyun" bhi.

1. Project samjha aur deployment guide padhi

Kyun: kya deploy ho raha hai, kis order mein, ye pata hona chahiye.

docs/DEPLOYMENT_GUIDE.md ko Hinglish bullets mein samjha.

2. Local par chalane ki koshish: port 8080 clash

Kyun local: AWS par bhejne se pehle machine par chala kar dekhna sasta aur fast hai.

docker compose up --build chalaya, lekin localhost:8080 par Jenkins ka login page khula. Matlab 8080 port pehle se kisi aur ke paas tha. Fix: compose mein port badalna (jaise 9090:3000) ya doosri service band karna.

3. AWS CLI login + Terraform settings

Kyun: Terraform ko AWS account mein resources banane ki permission chahiye.

aws configure, phir terraform.tfvars mein region, GitHub repo URL, aapka IP (admin_cidr), email.

4. Provision: ek command se poora AWS setup

Kyun Terraform: haath se 30 resources banana galti wala aur slow hai. Code se ek baar likha, kabhi bhi dobara bana lo.

2 EC2 servers, Elastic IPs, ECR, IAM roles, security groups, SNS, CloudWatch log group, secrets. Dono servers SSM mein Online dikhe.

5. Build #1 se #4: Container Security Gate fail

Phase 1-3 sab pass. Phase 4 par error: ScanNotFoundException: Image scan does not exist.

Repo par scanOnPush=true dobara set kiya, lekin fark nahi pada (Terraform mein ye pehle se true tha).

6. Build #5: retry wala script bhi fail

Phase 4 mein 30 baar retry ka loop daala. Lekin wo pehle hi attempt par ruk gaya (exit 254). Wajah section 7 mein hai.

7. Build #6: Phase 4 comment out kiya, deploy ho gaya

Phase 4 ko // se band kiya. Pipeline aage badhi, approve hua, app live ho gayi aur "Deployed" email aaya.

⚠️ Ye temporary jugaad hai. Abhi container scan bilkul nahi ho raha.

8. CloudWatch mein logs dekhna seekha

Log group /oneclick-erp/app, Logs Insights queries, live tail.

9. UI change: fonts bold (Build #7)

app/public/styles.css mein font-weight badhaya. Commit, push, build, approve.

10. GitHub Webhook: push par automatic build

Kyun: har baar Jenkins kholke "Build Now" dabana manual kaam hai. Webhook se push hote hi pipeline khud chalti hai.

GitHub ke webhook IP ranges (api.github.com/meta ke hooks) github_webhook_cidrs mein daale. Pehli baar string diya to error aaya, kyunki Terraform ko list chahiye thi: ["a", "b"]. Fix ke baad terraform apply, phir GitHub mein webhook add kiya. Build #8 push se khud chala.

11. Build #8: AI report 403 error

Email aaya, lekin likha tha anthropic.claude-opus-5-5 is not available for this account. Isliye rule-based report bheja gaya. Release ruka nahi (design hi aisa hai).

12. Marquee header (Build #9)

Header mein scrolling "🚀 OneClick ERP - Superfast Deployment 🚀". Push hua, webhook se build chala.

13. Bedrock use-case form: account authorized nahi

Bedrock ka "Model access" page AWS ne band kar diya hai. Anthropic models ke liye use-case form bharna padta hai, lekin aapke account par message aaya: "create a support case". Ye abhi pending hai.

7. Problems aur unke asli fix

Har problem: kya dikha, asli wajah kya thi, sahi fix kya hai.

Problem 1: ECR scan "does not exist" (sabse important)

Asli wajah (aapke AWS account mein check kiya) ECR ka registry-level scanning setting ye hai: 
"scanType": "BASIC",
"rules": []
rules khaali hai, matlab registry kisi bhi repo ki image scan nahi kar rahi. Registry-level setting repo ki scanOnPush setting se upar chalti hai. Isliye repo par scanOnPush=true hone ke baad bhi images #7, #8, #9 ka scan status None hai. Pipeline scan ka wait kar rahi thi jo kabhi shuru hi nahi hua.
Sahi fix (industry standard): registry par scan-on-push rule lagao 
aws ecr put-registry-scanning-configuration `
  --region us-east-1 `
  --scan-type BASIC `
  --rules '[{"scanFrequency":"SCAN_ON_PUSH","repositoryFilters":[{"filter":"*","filterType":"WILDCARD"}]}]'
Phir original Phase 4 wapas lao (wo first commit mein tha): 
cd d:\oneclick-erp
git show a8e9294:Jenkinsfile > Jenkinsfile.original
# Jenkinsfile.original se "Phase 4" wala stage copy karke Jenkinsfile mein wapas lagao
# phir commit + push
Behtar ye hai ki ye rule Terraform mein bhi likha jaye (aws_ecr_registry_scanning_configuration resource), taaki agli baar provision karne par apne aap lag jaye.
Retry wala script kyun fail hua? (Build #5)
  • Jenkins ka sh step script ko /bin/sh -xe se chalata hai. -e ka matlab: koi bhi command fail hui to script turant band.
  • aws ecr describe-image-scan-findings ne error diya (scan tha hi nahi), to script pehle hi attempt par band ho gaya. Log mein SCAN_STATUS= khaali dikha, phir exit 254.
  • for i in {1..30} bash ka syntax hai, plain sh mein kaam nahi karta. Original Jenkinsfile har stage ke upar #!/bin/bash lagati thi, naye code mein wo nahi tha.
  • Aur sabse badi baat: retry se kuch nahi hota jab scan shuru hi nahi ho raha. Asli fix registry rule hai.

Problem 2: AI report 403 (Claude not available)

Wajah Pipeline default model anthropic.claude-opus-5-5 use karti hai (infra/terraform/variables.tf mein bedrock_model_id). Aapke AWS account ko Anthropic models ki access abhi nahi mili, kyunki use-case approval pending hai aur aapka account khud form submit nahi kar sakta.
  • Step 1: AWS Console → Support → Create case. Likho ki Bedrock par Anthropic Claude models ki access chahiye, use case: CI/CD release summaries. AWS reply karega.
  • Step 2: Access milne ke baad koi rebuild nahi chahiye. Agle build mein AI summary apne aap aayegi.
  • Doosra model use karna ho: terraform.tfvars mein bedrock_model_id = "..." set karke terraform apply. Dhyan rahe: ye Jenkins server ka user-data badalta hai, to Jenkins server dobara banega aur build history chali jayegi. App server aur data safe rehte hain.
  • Tab tak: rule-based report theek hai. Release nahi rukta.

Problem 3: Local par port 8080 busy

Compose file app ko 8080 par map karti hai. Aapke PC par wahan pehle se kuch chal raha tha. Fix: docker-compose.yml mein "9090:3000" karke http://localhost:9090.

Problem 4: github_webhook_cidrs type error

Variable ka type list(string) hai. String "a,b,c" nahi chalega. Sahi: ["a", "b", "c"]. Seekh: Terraform error mein "list of string required, but have string" dikhe to brackets lagao.

Problem 5: git add "did not match any files"

Aap infra\terraform folder mein the aur Jenkinsfile root par hai. Git path current folder se dekhta hai. Fix: cd d:\oneclick-erp karke commands chalao, ya poora path do (infra/terraform/variables.tf).

9. Aage kya karna hai (priority order)

1️⃣ Container scan wapas chalu

Registry scan rule lagao (section 7 ka command), original Phase 4 wapas lao, push karo. Bina iske vulnerable image production tak ja sakti hai.

2️⃣ Registry rule Terraform mein

aws_ecr_registry_scanning_configuration resource add karo, taaki setup code mein rahe, haath se nahi.

3️⃣ Bedrock access

AWS support case kholo. Access milte hi AI summary apne aap aane lagegi.

4️⃣ HTTPS (AWS par)

AWS stack abhi HTTP par hai — ALB + ACM certificate chahiye. GCP par ye ho chuka hai (Caddy + Let's Encrypt), neeche dekho.

5️⃣ Terraform state S3 mein

State file mein generated passwords hote hain. S3 backend (encrypted) use karo, laptop par mat rakho. GCP side par ye already GCS backend mein hai.

6️⃣ Jenkins size

Builds slow/crash hon to jenkins_instance_type wapas t3.medium.

GCP par ye ab ho chuka hai

✅ HTTPS

app_domain set karo aur Caddy apne aap Let's Encrypt certificate le aata hai, HTTP ko HTTPS par redirect karta hai. Domain na ho to plain HTTP par chalta rehta hai. Pipeline ka smoke test certificate aur redirect dono check karta hai.

✅ Database backup

Roz 02:00 UTC par pg_dump ek versioned Cloud Storage bucket mein jaata hai, backup_retention_days ke baad apne aap delete. Restore ke liye app VM par sudo /opt/erp/db-restore.sh.

✅ Integration tests

Pipeline ek throwaway PostgreSQL uthaati hai aur wo cheezein test karti hai jo fake DB se prove nahi hoti — failed order poora rollback hota hai, aur do concurrent orders same product ko oversell nahi kar sakte.

Jo abhi bhi nahi hai (honest list) Jenkins ek hi VM par hai (HA nahi), sab kuch ek hi zone mein hai (multi-region failover nahi), PostgreSQL container mein hai managed service nahi, aur horizontal auto-scaling nahi hai. Ye sab asli production ke liye chahiye hote hain — abhi nahi hain.

Tests local par

cd d:\oneclick-erp\app

Code change → production

cd d:\oneclick-erp

Terraform

cd d:\oneclick-erp\infra\terraform

terraform apply                                 # badlo
terraform output                                # saare URLs

AWS checks

# servers SSM mein online hain?
aws ssm describe-instance-information --region us-east-1 --query "InstanceInformationList[*].[InstanceId,PingStatus]" --output table

# images aur unka scan status
aws ecr describe-images --repository-name oneclick-erp --region us-east-1 --query "imageDetails[*].[imageTags[0],imageScanStatus.status]" --output table

# registry scanning setting
aws ecr get-registry-scanning-configuration --region us-east-1

Rollback

# Recommended: bad commit ko revert karo, normal pipeline se jayega
git revert <bad-commit>
git push origin main

# Emergency (gates skip): purani image direct deploy
aws ssm send-command --instance-ids <app_instance_id> --document-name AWS-RunShellScript --parameters 'commands=["/opt/erp/deploy.sh <ecr-url>:<purana-tag>"]'

CloudWatch Logs Insights (errors)

fields @timestamp, msg, error
| filter level = "error"
| sort @timestamp desc

11. Security: is project mein kya achha hai

  • SSH nahi: port 22 kabhi khula nahi. Sab kuch SSM se, aur har command log hoti hai.
  • Least privilege IAM: Jenkins sirf ek ECR repo, ek SNS topic, ek server ko chhoo sakta hai.
  • Secrets Git mein nahi: Terraform generate karta hai, SSM Parameter Store mein SecureString.
  • Jenkins sirf aapke IP se: plus GitHub webhook ke IP ranges.
  • Postgres bahar se band: sirf Docker ke private network par.
  • Container hardening: non-root user, runtime image se npm/yarn hataye.
  • IMDSv2 + encrypted disks dono servers par.
Dhyan do Jenkins admin password chat/screenshots mein dikh chuka hai. Agar wo kahin public jagah share hua ho, to password badal do. Aage se terraform output -raw ... ka output screenshot mein mat daalo. Aur jab tak Phase 4 band hai, image scan nahi ho raha. Ise jaldi chalu karo.

14. Quick quiz (khud ko check karo)

1. Build #1-#4 ka Phase 4 kyun fail ho raha tha?

Registry-level rules: [] ki wajah se scan kabhi shuru hi nahi hua. Retry se ye fix nahi hota.

2. Jenkins app server par deploy kaise karta hai?

SSM se. Port 22 khula hi nahi hai, aur har command log hoti hai.

3. AI report fail ho to kya hota hai?

AI report kabhi release nahi rokta. Build #8 mein yahi hua.

4. Image tag 8-a86f45df ka matlab?

Har tag unique aur immutable hai, isliye pata rehta hai kaunsa code production mein hai.

5. Webhook ke liye Jenkins security group mein kya add kiya?

Sirf GitHub ke webhook IPs ko allow kiya. Poori duniya ke liye Jenkins nahi khola.
